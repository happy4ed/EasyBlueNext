# EasyBlue Next 0.3.4

## 드롭다운 테마 수정

ComboBox와 ComboBoxItem 전용 스타일이 빠져 앱의 글자색과 Windows 기본 팝업 배경이 섞여 있었다. 라이트/다크 모두 Panel/Ink/Selected/SoftButton 색을 사용하며 펼친 목록, 선택 표시, 마우스 강조, 키보드 포커스와 스크롤에 공통 테마를 적용했다. 클립보드·특수키·대상 기기 목록에 함께 적용한다.

## 초기 자동 전환 준비

사용자가 ‘단축키로 폰에 한 번 갔다 오기 전에는 자동 전환이 동작하지 않는다’고 보고했다. 기존 검색 경로는 후크만 설치하고 입력 엔진에 DeviceClient를 연결하는 처리는 Switch에서 수행했다. 초기 검색 직후 입력 세션을 연결하고 PC 가장자리 감시를 준비하도록 수정했다. Bluetooth 미연결 상태에서도 로컬 감시를 준비하며, 이미 연결된 대상이 있을 때만 원격 해제를 시도한다. 원격 해제 응답이 없다는 이유로 로컬 경계 감시를 막지 않는다. 실제 전환 전의 키 해제 확인은 유지한다.

PreparePcInput은 관측된 키/특수키/마우스 해제만 보내고 PC 대기 표시로 마친다. 연결·페어링 명령은 보내지 않는다. 준비 또는 후크 설치가 실패하면 5초 뒤 다시 준비한다. 페어링 중/실패 후 일시 중지에는 복구를 끼워 넣지 않는다. 감시 준비 성공 시 이전 대기·차단 상태를 초기화한다. 단축키 입력 중 상태는 실제 활성 창과 키보드 포커스로 계산한다. 경계 위치/대기 시간/양방향 전환 방식은 유지한다.

자동 전환의 일시 중지 이유와 초기 준비 상태는 UI에 표시하며 진단 시작을 누른 동안만 로그에 남긴다. 평소에는 로그를 기록하지 않는다. 사용자 PC의 최초 증상을 실제로 재현했다거나 모든 원인을 확정했다고 주장하지 않는다.

검증: 코어 검사183개(초기 PC 대기 준비, 연결/페어링 비발생, 거부 응답, 잘못된 키 누름 거부 포함), Windows 크로스 빌드, 라이트/다크 팝업·선택·호버 색상 대비 계산, 설치/포터블 추출 해시 비교. 실제 Windows 팝업 조작과 콜드 스타트 자동 전환은 현장 확인이 필요하다.

시작프로그램은 사용자 폴더 바로가기 방식(로그인 후 트레이 실행)을 유지한다. 로그인 전 서비스는 추가하지 않는다.
