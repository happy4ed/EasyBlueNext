# EasyBlue Next 0.3.3

사용자가 설치와 앱 내부에서 예약 작업 등록 재확인 실패를 보고했다. 이전 실패의 정확한 Windows 원인은 아직 재현하지 못했다. 예약 작업 생성 방식은 제거하고, Microsoft가 안내하는 사용자 시작프로그램 폴더의 EasyBlue Next.lnk로 전환했다. IShellLinkW/IPersistFile로 실행파일, --background, 작업 폴더를 설정하고 저장한 바로가기를 다시 읽어 검증한다. UI에서는 STA 전용 스레드로 처리한다. 경로 비교는 대소문자와 작업 폴더의 끝 구분자를 정규화한다.

새 바로가기가 검증되면 이전 EasyBlueNext 예약 작업과 Run 등록을 정리한다. 이전 작업 정리에 실패하면 새 바로가기는 유지하고 구체적인 오류 코드와 정리 필요 상태를 표시한다. 해제는 바로가기와 이전 등록을 함께 제거한다. 앱의 ‘Windows 시작 앱’ 버튼에서 OS의 실행 허용 여부를 확인할 수 있다. 바로가기 등록 확인은 실제 로그인이 성공했다는 뜻이 아니다. 예약 작업의 재시도·10초 지연 기능은 제거됐다.

연결 토스트는 활성 모니터의 오른쪽 아래 작업 영역에 표시한다. 너비370, 글자14/12, 네이티브 최상위 배치와 700ms 최소 연결 중 표시를 적용한다. 성공은2.6초, 실패는6초 표시한다. 상태 표시만 지연하며 실제 Bluetooth 연결이나 입력 전환을 기다리게 하지 않는다. 연결 제한10초, PC 복귀 및 기존 자동 전환 판정은 유지한다.

코어 검사176개 및 Windows용 빌드·설치파일 대조로 검증한다. 실제 Windows .lnk 생성/로그인·이전 작업 정리 및 토스트 시인성은 이 Linux 환경에서 시험하지 못했다. 평소에는 로그를 남기지 않는다.
